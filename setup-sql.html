Setting up SQL

Installing MySQL or MariaDB on macOS and Windows, checking that it actually started, and loading the course demo database so you have something to query. Fifteen minutes, most of it waiting for a download.

Everything in this course that is not a diagram eventually becomes SQL, and SQL is one of those things you cannot learn by reading. You need a server you can break, reset and break again on your own machine — which is all this appendix is for.

A.1Which one to install

You can choose either MySQL or MariaDB. MariaDB is a drop-in replacement for MySQL: same client command, same SQL, same port. Everything in this course works identically on both, and nothing on this site depends on which you picked.

 pick this if
MySQLyou are on Windows — the official installer bundles the server, the command-line client and Workbench in one download
MariaDByou are on macOS with Homebrew, or you simply prefer it; it is the one the answer keys on this site were checked against
What "SQL" is and is not

SQL is the language. MySQL and MariaDB are servers that speak it. What you are installing is a program that sits in the background holding your databases, plus a client that connects to it and sends it statements. That is why there are two separate steps below — installing, and then starting — and why forgetting the second one is the most common thing to go wrong.

A.2macOS

1. Install Homebrew, if you have not already

Homebrew is a package manager for macOS, and the easiest way to install software like MySQL or MariaDB. Open Terminal and run:

/bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"

It will ask for your password and may ask you to install Apple's command-line developer tools first. Let it.

2. Install the server

brew install mysql        # or:
brew install mariadb

3. Start the service

brew services start mysql        # or:
brew services start mariadb

brew services starts the server now and arranges for it to start again when you log in, which is what you want — otherwise the server is gone after the next restart and nothing connects.

4. Secure the installation

Good practice, and it is where you set the root password:

mysql_secure_installation

Follow the prompts to set the root password, remove anonymous users, disallow remote root login, and remove the test databases. Saying yes to all of them is fine for a course machine.

5. Connect

mysql -u root -p

It prompts for the root password you just set. A mysql> or MariaDB [(none)]> prompt means you are in; exit gets you out again.

A.3Windows

1. Download the installer

Go to the MySQL downloads page and get the MySQL Installer for Windows. Alternatively, download MariaDB from its own website; the MariaDB installer follows the same shape as the steps below.

2. Run it

Choose Developer Default or Server Only, depending on your needs. Developer Default brings the MySQL Server, MySQL Workbench and the other client tools in one go, and is the simpler choice if you are not sure.

3. Configure the server

During installation you will be prompted to configure the MySQL Server:

  • server type, and the port — the default is 3306, and there is no reason to change it;
  • the authentication method — use the recommended one;
  • a root password. Write it down. There is no convenient way to recover it, and you will need it every time you connect.

4. Finish, then connect

Once installation completes, MySQL is installed and ready. To use it from the command line, search the Start menu for MySQL Command Line Client and open it; it asks for the root password you set during installation. MySQL Workbench is the graphical alternative and is installed alongside it under Developer Default.

If you want Workbench separately

MySQL Workbench is a graphical tool for managing and querying your databases. It can be installed through the MySQL Installer, or on its own from the MySQL Workbench downloads page.

A.4Check it works

On either system, open a terminal (or Command Prompt) and ask the client for its version:

mysql --version

If it is installed correctly this returns the version of MySQL or MariaDB that is running — something like:

mysql  Ver 8.0.43 for macos14 on arm64 (Homebrew)

or, on MariaDB:

mariadb  Ver 15.1 Distrib 10.11.14-MariaDB, for debian-linux-gnu (x86_64)
A version number is not a running server

mysql --version asks the client what it is, and the client is just a program on disk. It answers happily even when no server is running. The real test is connecting — mysql -u root -p — and the first section of §A.7 is about what to do when that fails.

A.5Your first session

Worth doing straight away, so that the next time you sit down to write SQL there is already something to write it against. The course demo file collegeDBdemo.sql builds a small college database — people, teachers, departments.

From a terminal, in the folder that holds the file:

mysql -u root -p -e "CREATE DATABASE collegeDB;"
mysql -u root -p collegeDB < collegeDBdemo.sql

Then connect and look around:

mysql -u root -p collegeDB
SHOW TABLES;
+---------------------+
| Tables_in_collegeDB |
+---------------------+
| Department          |
| Discipline          |
| Person              |
| Teacher             |
+---------------------+

SELECT * FROM Person;
+------+-------+-----------+
| id   | name  | yearBorn  |
+------+-------+-----------+
| 1001 | Blue  |      1970 |
| 1002 | Red   |      NULL |
| 1003 | Pink  |      NULL |
| 1004 | Green |      1980 |
+------+-------+-----------+

If you get those two results, your installation is working and you are ready for everything else on this site.

Four things worth knowing on day one
  • Every statement ends with a semicolon. Without it the client just waits, showing ->, for the rest of a statement you thought you had finished.
  • SHOW DATABASES; lists what is on the server; USE name; switches to one; SHOW TABLES; lists what is in the current one.
  • Keywords are not case-sensitive, but on some systems table names are — Person and person may be different tables on Linux and the same one on Windows. Type them exactly as they were created.
  • To run a file instead of typing: SOURCE filename.sql; from inside the client, or mysql -u root -p dbname < filename.sql from the shell.

A.6Graphical clients

Optional. If you would rather not work at the command line:

  • DBeaver — a cross-platform database management tool; works with MySQL, MariaDB and most other servers.
  • MySQL Workbench — the official MySQL GUI, for database design and query management. Already present if you chose Developer Default on Windows.

Both connect to the server you just installed: host localhost, port 3306, user root, and the password you set. A GUI is genuinely nicer for reading results and for drawing schema diagrams; it is worth being able to work without one too, since an exam question will not come with a mouse.

A.7Troubleshooting

“Can’t connect to local MySQL server through socket” / “Can’t connect to server on 'localhost'”

The client is fine; the server is not running. This is the single most common problem, and it usually means the machine was restarted since you installed.

macOS:

brew services start mysql        # or mariadb
brew services list               # shows "started" or "none"

Windows: open Services from the Start menu, find MySQL80 (or similar), and start it. Set its startup type to Automatic so this does not recur.

“command not found: mysql”

The program is installed but your shell cannot find it — a PATH problem, not an installation problem.

macOS, Apple silicon: Homebrew installs under /opt/homebrew, which an older shell profile may not include. Check with brew --prefix mysql, then add its bin directory to your PATH, or run the full path once to confirm the program is there.

Windows: use the MySQL Command Line Client from the Start menu, which knows where it lives, or add MySQL's bin folder to the system PATH.

“Access denied for user 'root'@'localhost'”

Wrong password, or no password where one is expected. Try mysql -u root -p and type it at the prompt rather than putting it on the command line — -p with the password attached has to have no space after it, which trips people up.

If the password is genuinely lost, the quickest route on a course machine is to uninstall and reinstall the server; there is nothing in it yet that you cannot rebuild from collegeDBdemo.sql. Recovering a root password is possible but fiddly, and not worth the time at this stage.

The client prints -> and will not do anything

It is waiting for you to finish the statement. You almost certainly missed the semicolon. Type ; and press return, and it will run what you typed.

If you are stuck mid-statement and want out, \c cancels the line.

“Unknown database” when loading the demo file

mysql … collegeDB < collegeDBdemo.sql connects to a database that must already exist — the redirect does not create it. Run the CREATE DATABASE collegeDB; step in §A.5 first.

Going further

Once this works, the useful habit is to keep your SQL in a .sql file rather than typing it into the client. You can re-run it after a mistake, you can hand it in, and you can see the whole query at once instead of one line of terminal. Every answer key on this site was produced that way — written to a file, run against a server, and the output pasted back.
